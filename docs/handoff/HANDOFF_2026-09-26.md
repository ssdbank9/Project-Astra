### 2.3 The `astra` command (from `src/astra/__main__.py`)

| Command | Arguments | What it does |
| --- | --- | --- |
| `astra init-owner` | `--email` (required), `--name` (default "App Owner") | Creates the first owner. That owner becomes the primary owner. |
| `astra serve` | `--host` (default `127.0.0.1`), `--port` (default `8765`) | Runs the web app with Python's `ThreadingHTTPServer`. Prints `Astra is running at http://<host>:<port>`. |
| `astra transfer-primary` | `--to EMAIL` (required), `--yes` | Makes an active secondary owner the primary owner. The old primary stays a secondary owner and is signed out everywhere. |
| `astra reset-password` | `--email` (required), `--yes` | Sets a new password for any active user. Needs an interactive terminal. The password is typed twice and never read from arguments, the environment or a pipe. |

`transfer-primary` and `reset-password` print the database path first and refuse
if the file does not exist. They never create one. Exit status is 0 when done,
1 when refused or aborted, and 2 for a usage error (README).

There are no other subcommands. There is no backup, export, health or version
command.

No other `ASTRA_*` variable exists. There is no setting for a trusted proxy,

## 5. Architecture map

### 5.1 Shape of the system

Astra is a single Python package, `astra` (`src/astra/`), with no third-party
runtime dependencies. One process serves a JSON API and the static front end
over plain HTTP. Data lives in one SQLite file in WAL mode.

```text
Browser (index.html + app.js + style.css, hash router)
    |  JSON over HTTP, session cookie + X-CSRF-Token header
    v
web.py   AstraHandler (BaseHTTPRequestHandler) on ThreadingHTTPServer
    |  one SQLite connection per request
    v
service.py   AstraService: every permission check and business rule
    |
    v
db.py   connect(), migrations v1-v20, transaction() = BEGIN IMMEDIATE
    |
    v
$ASTRA_HOME/astra.sqlite3 (+ -wal, -shm)
```

newer than the code is refused with "Database was created by a newer Astra
version." That means an upgrade cannot be rolled back by downgrading the code;
only a restore of the pre-upgrade backup rolls it back.

Notes:

- A designated approver who is not a manager may file Owner requests
  (including a hold). This includes the Chairman when listed as an approver
  (review 13b I1). Whether the Chairman and viewers should stay in the reviewer
  and approver lists is an open question for Aly.
- Nobody can approve or reject an Owner request they filed.
- Older assignments that break the 3FQEKB rules are kept and flagged "Needs
  a new assignee" or "Collaborator not allowed". The Chairman (even as a
  legacy assignee) and a flagged collaborator cannot submit. Neither can a
  project viewer who holds a **top-level** task from before the rules, or
  since being demoted from member: ticket G1PPV7 closed that gap
  (`_may_submit` now applies the 3FQEKB rule to the assignee too, reading the
  role at submit time). The panel hides Submit for them
  (`permissions.can_submit` is false) and the task stays flagged until
  someone reassigns it. A manager or owner can still submit it.
- Sign-in never locks anyone out. A wrong password or unknown email returns
  401 "Incorrect email or password." There is no limit on guessing, so the
  hosted deployment should rate-limit in front of Astra (README; Q11).
- Users who are not owners cannot change their own password today. There is no
  forced password change at first sign-in.

## 9. Known gaps and follow-ups from the reviews

### 9.1 Not verified by anyone

- No real phone or tablet run (tablet long press is untested; Playwright
  emulation only).
- No screen-reader run (NVDA or VoiceOver).
- Real browser zoom at 200% only partly checked.
- No multi-user load test on real hardware.
- Nothing deployed; no HTTPS, backup or restore exercised.

### 9.2 Behaviour left as it is, by design or as a recorded call

- Lock chips, banners, flags and the Inbox "Approving overrides" lines show the
  last load. There is no live refresh; the server rechecks at write and
  decision time (12b I3).
- A lease held by someone whose access is revoked blocks others for up to 60 s
  unless an owner force-unlocks it (12b I4).
- Dragging a parent's Gantt bar moves only the parent; `is_milestone` is ignored
  by the impact check (12b I5).
- A finish-to-start link counts as broken only when the successor starts before
  the predecessor's due day (12b I1).
- A card that enters Blocked because of a dependency is not refused by a
  Blocked WIP limit (12c I4, documented in the README).
- `bulk_undo` scans the project's `bulk_change_undone` events; fine now,
  unbounded later (12c I5).
- An owner's board Undo passes the dependency override itself (12d I1).
- The importer and templates bypass the WIP and dependency gates; both are
  owner-only (12d I2).
- A manager's accept request on a waiting task is filed, and the owner is asked
  at decision time.
- A bulk Undo that would restore the Chairman as owner is refused as a whole.
- Putting a flagged task on hold needs a new responsible person.
- The Chairman as an approver can still file protected-action requests
  (13b I1).
- Unrated tasks sort below Low (QY0WG2; badge only).
- The login-attempt history has no index on `attempted_at` yet (3M2AYA, left
  for the next schema bump).
- The blocked-notice cap is soft under concurrency (KBWY86).

### 9.5 Production gaps in the code today

- `astra serve` is Python's `ThreadingHTTPServer`. The README says not to expose
  it directly to the internet. No request timeouts are set.
- No awareness of a reverse proxy: `login_attempts.ip` stores
  `client_address[0]`, which is `127.0.0.1` behind Caddy.
- No health endpoint (use `GET /`, which returns the page without signing in).
- No backup command, no export of the whole database, no restore tooling.
- No forced password change at first sign-in; non-owners cannot change their
  own password.
- No email or other outbound notification; password recovery goes through an
  owner.
- Attachment links point at paths on the server's own disk, so on the hosted
  server they should stay off (`ASTRA_ATTACHMENT_ROOTS` unset) until hosted
  uploads (MXY7BG) exist.
- No structured logging; access log lines go to stderr.
- No CI workflow (`.github/` does not exist).

## 10. Risks

| Risk | Why it matters | Mitigation |
| --- | --- | --- |
| Development server on the internet | `ThreadingHTTPServer` has no timeouts and was built for local use | Bind to `127.0.0.1`, put Caddy in front, add timeouts in a hardening ticket |
| Unlimited password guessing | Aly chose no lockout (3M2AYA) | Rate-limit `/api/login` at the proxy or with fail2ban (6BXYJZ) |
| No tested backups | SQLite file is the only copy | Build and prove backup and restore before any real user (TRPV3J) |
| Oracle Always Free limits | Oracle warns that capacity can be unavailable and idle instances may be reclaimed (per the 2026-09-20 handoff) | Off-host backups, a desktop recovery path, watch tenancy notices |
| One-way migrations | Newer schema refuses older code | Back up before every upgrade; roll back by restore |
| 33 tickets unaccepted | Merging before signoff ships work Aly has not accepted | Aly signs off first (phase A) |
| Branch divergence | PR #4 is stale and held; `main` has PR #3 ticket files | Follow the merge plan in `NEXT_STEPS.md` phase A |
| Public repository | Anything committed is public | Secrets only on the server, never in git |
| Large files | `service.py` 5421 lines, `app.js` long lines | Refactor only behind tests, one ticket at a time |
| Docs drift | Matrix and glossary lag the code | Phase A doc ticket |
| Codex push credentials on Windows | Codex once failed with `SEC_E_NO_CREDENTIALS` and uploaded through the browser, which produced CRLF files | Push from an environment with working git credentials; check for CR bytes before pushing |
| Single timezone | "Today" is always `Asia/Karachi` | Fine for the pilot; make it a setting if users are elsewhere |
